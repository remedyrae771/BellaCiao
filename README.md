# Bella Ciao · Cucina

Кухонное приложение для итальянской траттории **Bella Ciao** (Алматы).
Работает в браузере на планшете или телефоне, ставится на главный экран как приложение (PWA) и работает без интернета.

## Возможности

- **Вход только по коду станции.** У каждой станции свой 4-значный код, у шеф-повара отдельный. После ввода кода сотрудник выбирает себя из списка поваров этой станции. Повара коды менять не могут, их меняет только шеф в разделе «Команда → Коды». После 5 неверных попыток вход блокируется на 30 секунд, после 10 минут бездействия выход автоматический (смена при этом не закрывается).
- **Смены и учёт часов.** На главной кнопки «Начать смену» и «Закончить смену» с таймером. Повар видит свои смены и часы за месяц в профиле.
- **Табель (шеф и су-шеф):**
  - кто сейчас на смене;
  - часы по каждому сотруднику за сегодня, неделю, месяц, прошлый месяц или любые даты;
  - выгрузка в CSV (Excel, Google Таблицы).
- **Только шеф:**
  - ставка ₸/час и сумма к оплате;
  - ручное исправление и добавление смен, если кто-то забыл отметиться; исправленные смены помечаются ✎;
  - предупреждение о сменах длиннее 16 часов.
- **Роли:**
  - *Повар* видит чек-листы своей станции, все ТТК и ТБ.
  - *Су-шеф* видит все станции, заполняет чек-листы, правит ТТК, смотрит табель (без сумм) и отчёт по чек-листам.
  - *Шеф-повар* может всё то же, а ещё управляет сотрудниками, ставками, кодами и сменами.
- **Станции:** холодный цех, горячий цех (паста), горячий цех (гриль), раздача (су-шефы), пицца-станция, кондитерский цех.
- **Чек-листы:** открытие, во время смены и закрытие. Изначально пустые — пункты заполняют шеф-повар и су-шефы (добавить, переименовать, поменять порядок, удалить). Повара только отмечают выполнение; у каждой отметки видно, кто и во сколько её поставил.
- **ТТК:** брутто и нетто, технология, подача, хранение, аллергены, поиск, пересчёт на нужное число порций.
- **Техника безопасности:** общие разделы и разделы по станциям, подтверждение «ознакомлен».

## Коды по умолчанию (шеф должен сменить их сразу!)

| Станция | Код |
|---|---|
| Холодный цех | 1111 |
| Горячий цех — Паста | 2222 |
| Горячий цех — Гриль | 3333 |
| Раздача (су-шефы) | 4444 |
| Пицца-станция | 5555 |
| Кондитерский цех | 6666 |
| Шеф-повар | 0000 |

Шеф-повар: Салим лучший (код шефа). Су-шефы: Маманбий Сметуллаев и Илья (код раздачи). Поваров станций (сейчас демо) шеф заменяет на настоящих в разделе «Команда → Сотрудники» и там же задаёт ставку.

## Запуск

Сборка не нужна, это статические файлы.

```bash
python3 -m http.server 8080
# открыть http://localhost:8080
```

Для работы на кухне выложите папку на любой статический хостинг с HTTPS (GitHub Pages, Netlify, Vercel). Затем откройте адрес на планшете и выберите «Добавить на главный экран».

## Структура

```
index.html        — точка входа
css/styles.css    — строгий рабочий дизайн: тёмно-синий, фирменные голубой и коралловый как акценты (Manrope)
js/data.js        — станции, коды по умолчанию, техника безопасности
js/ttk-data.js    — ТТК ресторана и таблица сроков хранения ПФ
js/sync.js        — общая база: синхронизация между устройствами
tools/build-artifact.py — сборка в один HTML для публикации на claude.ai
js/app.js         — логика приложения
sw.js             — офлайн-режим
manifest.json     — установка как приложение
```

## Общая база (связь между устройствами)

В опубликованной версии (страница на claude.ai) данные хранятся в общей базе страницы (`js/sync.js`) и сразу видны на всех устройствах:
- **общими становятся** чек-листы и отметки, смены и табель, сотрудники и ставки, коды станций, ТТК и подтверждения ТБ;
- **одновременные действия не теряются:** каждая смена и каждая отметка пишутся слиянием, поэтому два повара могут отмечаться одновременно;
- **кто может вносить данные:** только те, кому владелец страницы выдал в меню «Поделиться» уровень «Участник» (Contributor) или выше; с уровнем «Просмотр» данные только видны.

Если открыть приложение вне claude.ai (локальный файл, свой хостинг), оно работает как раньше: данные хранятся только на этом устройстве.

## Важно

- Данные хранятся **на устройстве** (localStorage). Если на кухне один общий планшет, это работает как есть. Чтобы синхронизировать несколько устройств и вести историю на сервере, нужен бэкенд (например, Supabase или Firebase). Это следующий шаг.
- ТТК ресторана — в `js/ttk-data.js` (перенесены с карт на кухне: 16 позиций завтраков и 34 ПФ) + таблица сроков хранения ПФ. Карты с пометкой «сверить» нужно проверить по бумажным оригиналам. Шеф и су-шефы правят и добавляют карты в приложении.
