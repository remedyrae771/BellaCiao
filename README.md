# Bella Ciao · Cucina

Кухонное приложение для итальянской траттории **Bella Ciao** (Алматы).
Работает в браузере на планшете или телефоне, ставится на главный экран как приложение (PWA) и работает без интернета.

## Возможности

- **Только для руководителей кухни.** Входят шеф-повар (свой код) и су-шефы (код раздачи), после кода нужно выбрать себя из списка. Повара в приложение не входят. Коды меняет только шеф в разделе «Команда → Коды». После 5 неверных попыток вход блокируется на 30 секунд, после 10 минут бездействия выход автоматический (смена при этом не закрывается).
- **Смены и учёт часов.** Руководитель отмечает свою смену на главной («Начать смену» / «Закончить смену» с таймером). Приход и уход поваров отмечает шеф или су-шеф во вкладке «Команда → Табель» кнопками «Пришёл» / «Ушёл»; в смене записано, кто отметил.
- **Табель (шеф и су-шеф):**
  - кто сейчас на смене;
  - часы по каждому сотруднику за сегодня, неделю, месяц, прошлый месяц или любые даты;
  - выгрузка в CSV (Excel, Google Таблицы).
- **Только шеф:**
  - ставка ₸/час и сумма к оплате;
  - ручное исправление и добавление смен, если кто-то забыл отметиться; исправленные смены помечаются ✎;
  - предупреждение о сменах длиннее 16 часов.
- **Роли:**
  - *Повар* в приложение не входит: он есть в списке сотрудников для табеля и оплаты.
  - *Су-шеф* видит все станции, заполняет чек-листы, правит ТТК, смотрит табель (без сумм) и отчёт по чек-листам.
  - *Шеф-повар* может всё то же, а ещё управляет сотрудниками, ставками, кодами и сменами.
- **Станции:** холодный цех, горячий цех (паста), горячий цех (гриль), раздача (су-шефы), пицца-станция, кондитерский цех.
- **Чек-листы:** открытие, во время смены и закрытие, по каждой станции. Пункты заполняют шеф-повар и су-шефы (добавить, переименовать, поменять порядок, удалить) и сами отмечают выполнение; у каждой отметки видно, кто и во сколько её поставил.
- **ТТК:** 245 карт (включая новогодний спешл с фото блюд) по разделам (блюда меню и полуфабрикаты): состав в граммах, выход, технология по шагам, хранение; переход от ингредиента-ПФ к его карте; поиск по названию и составу; пересчёт на порции и замесы.
- **Советы:** профессиональные приёмы и цифры по разделам (мясо и птица, паста, пицца, соусы, холодный цех, кондитерка, вкус и подача, безопасность продукта, кухня и команда), «совет дня» на каждый день.
- **Техника безопасности:** общие разделы и разделы по станциям, подтверждение «ознакомлен».

## Коды по умолчанию (шеф должен сменить их сразу!)

| Кто | Код |
|---|---|
| Шеф-повар (Салим лучший) | 0000 |
| Су-шефы (Маманбий Сметуллаев, Илья) | 4444 |

Поваров станций (сейчас демо) шеф заменяет на настоящих в разделе «Команда → Люди» и там же задаёт ставку.

## Свой адрес и своя база (без аккаунтов claude.ai)

Адрес: **https://remedyrae771.github.io/BellaCiao/** (GitHub Pages; публикуется автоматически при каждом изменении ветки `main`, файл `.github/workflows/pages.yml`).

Общая база — Firebase Firestore (бесплатный тариф). Повара заходят только по коду станции. Настройка один раз:
1. **Firebase:** выполнить шаги из `js/firebase-config.js`: создать проект, включить Firestore и анонимный вход, вставить настройки, опубликовать правила из `firestore.rules`.
2. **GitHub:** в репозитории открыть Settings → Pages → Source: **GitHub Actions**.

Пока `FIREBASE_CONFIG` не заполнен, приложение на этом адресе хранит данные только на устройстве.

## Запуск

Сборка не нужна, это статические файлы.

```bash
python3 -m http.server 8080
# открыть http://localhost:8080
```

Для работы на кухне выложите папку на любой статический хостинг с HTTPS (GitHub Pages, Netlify, Vercel). Затем откройте адрес на планшете и выберите «Добавить на главный экран».

## Структура

```
index.html        — точка входа
css/styles.css    — дизайн-система в стиле iOS: системный шрифт, сгруппированные списки, «стеклянные» шапка и таб-бар, светлая и тёмная тема

js/ttk-data.js    — ТТК ресторана и таблица сроков хранения ПФ
js/tips-data.js   — советы для профессиональной кухни (вкладка «Советы»)
js/sync.js        — общая база: синхронизация между устройствами
js/firebase-db.js — подключение к Firebase Firestore
js/firebase-config.js — настройки Firebase (заполнить)
firestore.rules   — правила доступа к базе Firebase
tools/build-artifact.py — сборка в один HTML для публикации на claude.ai
tools/parse-ttk-xls.py  — разбор выгрузки ТТК (.xls) из учётной системы
js/app.js         — логика приложения
sw.js             — офлайн-режим
manifest.json     — установка как приложение
icons/            — иконки для экрана «Домой» (PNG для iPhone и Android)
```

## Общая база (связь между устройствами)

В опубликованной версии (страница на claude.ai) данные хранятся в общей базе страницы (`js/sync.js`) и сразу видны на всех устройствах:
- **общими становятся** чек-листы и отметки, смены и табель, сотрудники и ставки, коды станций, ТТК и подтверждения ТБ;
- **одновременные действия не теряются:** каждая смена и каждая отметка пишутся слиянием, поэтому два повара могут отмечаться одновременно;
- **кто может вносить данные:** только те, кому владелец страницы выдал в меню «Поделиться» уровень «Участник» (Contributor) или выше; с уровнем «Просмотр» данные только видны.

Если открыть приложение вне claude.ai (локальный файл, свой хостинг), оно работает как раньше: данные хранятся только на этом устройстве.

## Важно

- Данные хранятся **на устройстве** (localStorage). Если на кухне один общий планшет, это работает как есть. Чтобы синхронизировать несколько устройств и вести историю на сервере, нужен бэкенд (например, Supabase или Firebase). Это следующий шаг.
- ТТК ресторана — в `js/ttk-data.js`: 202 карты из выгрузки учётной системы (блюда меню и полуфабрикаты), завтраки, несколько ПФ с фото кухни и новогодний спешл с уткой (7 блюд с фото в `images/ttk/` и 12 ПФ). Новую выгрузку (.xls) разбирает `tools/parse-ttk-xls.py`. Карты, которые шеф правил в приложении, при обновлении не перезаписываются.
